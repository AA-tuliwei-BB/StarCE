## 3. Runtime vs pg-end2end Hot Cache Comparison

TC and SB results are consistent across both pipelines under hot cache (< 10% difference), verifying measurement reliability.

| Method | Runtime | pg-end2end |
|------|:------:|:------:|
| TC | 0.877s | 0.952s |
| SB | 1.154s | 1.282s |
| PG native | 1.089s* | 1.171s |

*Runtime PG value (no hint, no per-subquery EXPLAIN) is 1.09s, consistent with pg-end2end 1.17s.
The Runtime `evaluate_runtime_postgres()` measured 1.74s includes pg_hint_plan parsing and per-subquery EXPLAIN overhead.

## 4. Core Findings

### Hot Cache: TrueCard dual nature

TrueCard is fastest under hot cache (0.88-0.95s), but degrades the most under cold cache (4.0-7.6x).
Precise cardinality estimates → PG chooses Nested Loop + Index Scan → HDD cold cache I/O bottleneck.

### Cold Cache Resilience: SafeBound

SafeBound has the smallest cold penalty (2.1x Runtime / 2.1x pg-end2end).
Conservative estimates → PG chooses Hash Join → sequential I/O → HDD-friendly.

### Ranking Change

```
Hot Cache: TC < SB < PG native
Cold Cache: SB < TC < PG native
```

### Plan Quality Consistency

For q0/q2/q8 queries: pg_hint_plan / C proxy injection / PG native all produce the same plan.
Row estimate differences are minor and do not change join type or join order.
