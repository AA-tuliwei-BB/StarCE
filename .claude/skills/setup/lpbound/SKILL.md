# LpBound Reproduction Environment Setup

LpBound uses an independent conda environment `lpbound` (Python 3.12, DuckDB 0.10.1), which is **incompatible** with the project's main environment TestEnv (DuckDB 1.5.2). DuckDB database files are not interchangeable; LpBound must build databases from CSV on its own.

## 1. Conda Environment

```bash
# Restore from snapshot
conda env create -f setup/lpbound/environment.yml
conda activate lpbound
```

Core dependencies:

| Package | Version | Purpose |
|----|------|------|
| python | 3.12.13 | |
| duckdb | 0.10.1 | Statistics storage and querying |
| ortools | 9.14.6206 | Python LP solver |
| pandas | 2.3.2 | Data processing |
| numpy | 2.3.2 | Numerical computing |
| tqdm | 4.67.1 | Progress bars |
| cython | 3.1.3 | C++ LpFlow extension compilation |
| poetry | 2.4.1 | Package management (source installation of lpbound) |

Environment snapshot file: [`environment.yml`](environment.yml)

## 2. CSV Data Preparation

### IMDB

Create symbolic links from `Benchmark/IMDB/`:

```bash
mkdir -p methods/LpBound/data/datasets/imdb
for f in Benchmark/IMDB/*.csv; do
    ln -sf "$(realpath $f)" "methods/LpBound/data/datasets/imdb/$(basename $f)"
done
```

### STATS

```bash
mkdir -p methods/LpBound/data/datasets/stats
for f in methods/SafeBound/Data/Stats/*.csv; do
    cp "$f" "methods/LpBound/data/datasets/stats/$(basename $f)"
done
```

### Case-Insensitive Symbolic Links

LpBound code forcibly lowercases table names to look up CSVs (e.g., `postLinks` → `postlinks.csv`), so lowercase symlinks must be created:

```bash
cd methods/LpBound/data/datasets/stats
for f in *.csv; do
    lower=$(echo "$f" | tr '[:upper:]' '[:lower:]')
    [ "$f" != "$lower" ] && ln -sf "$f" "$lower"
done
cd methods/LpBound/data/datasets/imdb
for f in *.csv; do
    lower=$(echo "$f" | tr '[:upper:]' '[:lower:]')
    [ "$f" != "$lower" ] && ln -sf "$f" "$lower"
done
```

## 3. DuckDB Database and Statistics Precomputation

LpBound's database management and statistics generation is an automated flow:

| Step | Function | Description |
|------|------|------|
| Create DB + import CSV | `DatabaseManager.create_or_load_db()` | Auto-create tables, import data, build FK indexes on first run |
| Statistics precomputation | `build_lpbound_statistics(config)` | Generate MCV tables, histogram tables, degree sequence aggregation, write to `norms` table |

Can be done interactively step by step, or build all benchmarks in one shot:

```bash
conda activate lpbound
python3 -c "
from lpbound.config.lpbound_config import LpBoundConfig
from lpbound.acyclic.lpbound import build_lpbound_statistics

# Using LpBound's own default parameters (p_max=10, include_l0=True, include_l_inf=True)
for benchmark in ['stats', 'joblight', 'jobrange', 'jobjoin']:
    cfg = LpBoundConfig(benchmark_name=benchmark)
    build_lpbound_statistics(cfg)
    print(f'{benchmark}: done')
"
```

**Time reference** (default params, measured):

| Benchmark | Tables | Time (L1) | Time (All) | DB File |
|-----------|------|-----------|------------|---------|
| stats | 8 | ~14s | ~16s | `stats_duckdb.db` |
| joblight | 6 | ~9s | ~13s | `joblight_duckdb.db` |
| jobrange | 8 | ~31s | ~38s | `jobrange_duckdb.db` |
| jobjoin | 21 | ~5s | ~9s | `imdb_duckdb.db` |

All `.db` files are located at `methods/LpBound/data/duckdb/`.

## 4. C++ Solver

The C++ solver (used for estimation time measurement) depends on the HiGHS linear programming library.

### 4.1 Compilation

Requires HiGHS linear programming library and nlohmann/json header-only library:

```bash
cd methods/LpBound/src/lpbound/cpp_solver

# Clone dependencies
git clone https://github.com/ERGO-Code/HiGHS.git --depth 1
git clone https://github.com/nlohmann/json.git

# Compile C++ solver
cd lpbound_parallel
bash compile.sh
```

Build artifact: `build/lpbound_parallel`

### 4.2 Input Data Preparation

The C++ solver requires LP constraint JSON files (`input_data/{benchmark}/`), converted from pre-built LP dumps:

```bash
cd methods/LpBound/src/lpbound/cpp_solver/lpbound_parallel

# Extract pre-built LP dumps (move extracted files into raw_input/)
unzip raw_input.zip
mkdir -p raw_input
mv jobjoin_subqueries joblight_subqueries jobrange_subqueries stats_subqueries raw_input/

# Generate JSON input data (convert from raw_input LP dumps)
conda activate lpbound
python create_input_files.py
```

> **Note**: The LP dumps in `raw_input.zip` were generated by upstream authors using their precomputed norms tables. These JSON files are only used for C++ solver **timing measurement**. To obtain estimates based on the **current norms tables**, run the Python `estimate()` (see step 4.3 accuracy workflow).

### 4.3 Accuracy Experiment (Obtain Cardinality Estimates)

Follow README Section 6.2 to run `accuracy_acyclic.py`, producing actual estimates using current norms tables:

```bash
cd methods/LpBound
conda activate lpbound
python benchmarks/experiments/accuracy_acyclic.py lpbound
```

Results are written to `results/accuracy_acyclic/{benchmark}/lpbound_{benchmark}_full_estimations.csv`, which can be compared against `truecardinality_*_full_estimations.csv` to compute errors.

### 4.4 Performance Experiment (Measure Estimate Time)

Follow README Section 6.3, using the C++ solver to measure LP solve time:

```bash
cd methods/LpBound
conda activate lpbound
python benchmarks/experiments/estimation_time.py
```

This script invokes the C++ `lpbound_parallel`, running sequential and parallel modes separately, writing results to `results/estimation_time/raw_results/`.

Per-subquery average time (measured):
- sequential: ~0.06-0.15ms
- parallel: ~0.2-7.6ms (all subqueries of the same query solved in parallel)

## 5. Path Mapping

Mappings in `paths.py`:

```
benchmark → db_name (WORKLOAD_TO_DB_MAP):
  jobjoin → imdb            (Full IMDB, 21 tables)
  joblight → joblight       (JOBLight, 6 tables)
  jobrange → jobrange       (JOBRange, includes range predicates)
  stats → stats             (STATS-CEB, 8 tables)

db_name → csv_dir (CSV_DATA_DIR_MAP):
  imdb → imdb
  joblight → imdb           (also reads from IMDB CSV)
  jobrange → imdb
  stats → stats
```

DB file: `methods/LpBound/data/duckdb/{db_name}_duckdb.db`

## 6. TestLpBound Execution

Once the environment is ready:

```bash
cd experiment
conda activate TestEnv          # Current project environment
python TestLpBound.py           # Build + Estimate
python TestLpBound.py --build-only
python TestLpBound.py --est-only
```

The script internally uses `conda run -n lpbound` to invoke the LpBound environment; no manual switching is needed.
