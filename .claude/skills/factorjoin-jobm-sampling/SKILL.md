```

  ├── === N === header lines

  └── SELECT COUNT(*) ... (subquery lines)

  ↓ remap_factorjoin_jobm.py

```

## Key Fixes (Already Merged)

### 1. PDF Dimension Issue (load_sample.py)

**Problem**: `eliminate_one_key_group` requires `factors[table].pdfs` and `oned_bin_modes` to have matching dimensions (both raw counts). The original code in `load_sample_imdb_one_query` divided pdfs by table_len to normalize them into probabilities, causing a dimension mismatch with `oned_bin_modes` (raw counts, e.g., 2.5M). `np.minimum(bin_modes, pdfs)` always returned probability values (< 1), and final estimates were all in the 0-1 range.

**Fix**:
- 1D pdf: keep raw counts (do not divide by table_len)
- 2D pdf: `outer = np.outer(pdf1, pdf2) / filter_size` (joint density, sum = filter_size)
- `_get_pdf_for_key` multiplies by `gt_factor.table_len` when reading from gt_factor to get raw counts

```python
# Wrong (fixed)
pdfs /= table_len  # Normalized to probability → dimension mismatch with oned_bin_modes

# Correct
# Keep raw counts, do not normalize
source_pdfs[subquery_alias][key] = pdfs  # sum ≈ filter_size

# 2D outer product: sum = filter_size (not 1 or filter_size²)
outer = np.outer(pdf1, pdf2) / fs
```

### 2. Alias Remapping (bound.py)

**Problem**: Subqueries use `table1`-style aliases (e.g., `title1`), while `table_buckets` and `equivalent_keys` use real table names (e.g., `title`). Direct lookup triggers `KeyError`.

**Fix**: In the `get_cardinality_bound_one` sampling mode branch, remap `join_keys` and `conditional_factors` to real table names via `tables_all` (alias→table mapping):

```python
join_keys = {tables_all[alias]: keys for alias, keys in join_keys.items() if alias in tables_all}
conditional_factors = {tables_all[alias]: factor for alias, factor in conditional_factors.items() if alias in tables_all}
```

### 3. equivalent_variables Completion (bound.py)

**Problem**: In sampling mode, `Factor` objects lack `equivalent_variables` (None), but `eliminate_one_key_group` requires `key_group in factors[table].equivalent_variables`.

**Fix**: Dynamically complete based on `equivalent_group` (obtained from `get_join_hyper_graph`):

```python
key_to_group = {k: PK for PK, keys in equivalent_group.items() for k in keys}
for factor in conditional_factors.values():
    if factor.equivalent_variables is None:
        new_equiv = [key_to_group[var] for var in factor.variables if var in key_to_group]
        for var, equiv_pk in zip(factor.variables, new_equiv):
            if equiv_pk not in factor.cardinalities:
                factor.cardinalities[equiv_pk] = factor.cardinalities[var]
        factor.equivalent_variables = new_equiv
```

### 4. Tables with More Than 2 Join Keys (bound.py)

**Problem**: `eliminate_one_key_group` only supports 2D factors (max 2 join keys per table). In JOBM, `movie_companies` has 3 join keys (company_id, company_type_id, movie_id), triggering `ValueError`.

**Fix**: In `get_cardinality_bound_one`, truncate join keys to the first 2 alphabetically:

```python
for alias in join_keys:
    if len(join_keys[alias]) > 2:
        join_keys[alias] = set(sorted(join_keys[alias])[:2])
```

Additionally, in `eliminate_one_key_group`, if `twod_bin_modes` is unavailable (because the table has 3+ schema join keys), approximate using 1D mode (independence assumption):

```python
if actual_key in self.table_buckets[table].twod_bin_modes:
    bin_modes = self.table_buckets[table].twod_bin_modes[actual_key]
    modes_slice = np.minimum(bin_modes[:, i] if idx_b == 0 else bin_modes[i, :], pdfs_slice)
else:
    bm_1d = self.table_buckets[table].oned_bin_modes[actual_key]
    modes_slice = np.minimum(bm_1d, pdfs_slice)
```

### 5. pkl Format (create_binned_cols.py)

When materializing, the pkl must store the `alias_to_table` field (main query alias→table name mapping) so `load_sample_imdb_one_query` can correctly identify table names during subquery evaluation:

```python
data = {
    "all_aliases": all_aliases,
    "all_columns": all_columns,
    "all_sqls": all_sqls,
    "results": results,
    "alias_to_table": alias_to_table,  # Required!
}
```

### 6. subquery_from_grouped.sql → subquery.sql Alignment

In `subquery_from_grouped.sql` (9472 lines), the same SQL may appear repeatedly across different main query groups. `subquery.sql` (6424 lines, unique) is the final benchmark standard.

Conversion script: `methods/FactorJoin/scripts/remap_factorjoin_jobm.py`

```python
# Same SQL with multiple estimates → take the mean
sql_to_preds = defaultdict(list)
for sql, pred in zip(grouped_sqls, grouped_preds):
    sql_to_preds[sql].append(pred)
remapped = [np.mean(sql_to_preds[sql]) for sql in target_sqls]
```

## Known Limitations and Improvement Directions

### Limitation 1: Empty Sampling Fallback Handling (Fixed)

**Original bug**: In `load_sample.py`, when sampling was empty, `table_len = gt.table_len` (full table row count, e.g., 234K), causing highly selective predicates (e.g., `country_code = '[sm]'`, only 1 row in the entire database) to produce estimates as high as 36 million, 7 orders of magnitude above the true value (0~2).

**Root cause**: Inconsistent with the original `sample_on_the_fly.py` handling. The original code set `table_len = 1` for empty sampling (conservative estimate), while our code incorrectly used the full table row count.

**Fix** (`load_sample.py` lines 80-85):
```python
if table_len == 0:
    # Empty sampling means very little data after filtering, conservatively set filter_size=1 (consistent with sample_on_the_fly.py)
    gt = table_key_equivalent_group[table_name]
    table_len = 1
    pdfs = gt.pdfs[key]  # Normalized probabilities, sum≈1, used as tiny raw counts
```
`pdfs` uses normalized probabilities (sum≈1) as tiny raw counts. After `np.minimum` with `oned_bin_modes` (in the millions) in `eliminate_one_key_group`, it produces very small values, correctly reflecting empty-sampling semantics.

**Post-fix Q-Error** (vs real.txt, 6424 entries):
- p50: 15.0x, p90: 1602x, p95: 9994x, p99: 93095x, max: 702669x
- Before fix: p50: 22.9x, p90: 5183x, p95: 27684x, p99: 446363x, max: 36292062x

Residual overestimation remains (p99 still 93K), because extremely sparse values like `[sm]` have 0 rows in the sample table, and the back-projected row count `1/(0.01) = 100` from `table_len=1` is still far larger than the true value (0~2). This is an inherent limitation of insufficient sampling rate.

### Limitation 2: Approximation for 3 Join-Key Tables
`movie_companies` has three join keys (company_id, company_type_id, movie_id), but the code truncates to the first 2 (alphabetically), ignoring the third. This may cause underestimation or overestimation.

**Improvement direction**: Support 3D factors, or use a better approximation (e.g., chain decomposition).

### Limitation 3: 2D Outer Product Independence Assumption
The joint distribution of two join keys is approximated using outer product (independence assumption). For strongly correlated columns (e.g., foreign key pairs in the same table), this assumption introduces error.

**Improvement direction**: Estimate the joint distribution directly from the sample data (if the sample is sufficient).

## Execution Commands

### Full JOBM Evaluation Pipeline

```bash
cd methods/FactorJoin

# 1. Train model (first time)
python run_experiment.py --dataset jobm --generate_models \
    --data_path ../../methods/SafeBound/Data/IMDB/{}.csv \
    --model_path checkpoints/jobm/model_jobm_default.pkl \
    --n_dim_dist 1 --bucket_method fixed_start_key \
    --db_conn_kwargs "dbname=imdbm user=postgres host=localhost port=5432" \
    --prepare_sample --sampling_percentage 1.0 --sampling_type ss \
    --query_file_location ../../Benchmark/workloads/JOBM/queries.sql \
    --materialize_sample

# 2. Evaluate subqueries
python run_experiment.py --dataset jobm --evaluate \
    --model_path checkpoints/jobm/model_jobm_default.pkl

# Output: Benchmark/workloads/JOBM/subquery/result/factorjoin.txt (9472 lines)

# 3. Convert to subquery.sql-aligned format
python scripts/remap_factorjoin_jobm.py

# Output: Benchmark/workloads/JOBM/subquery/result/factorjoin_remapped.txt (6424 lines)
```

### Key Parameter Descriptions

| Parameter | Value | Description |
|------|-----|------|
| `--dataset` | `jobm` | Trigger JOBM-specific branch |
| `--n_dim_dist` | `1` | Sampling mode only supports 1D |
| `--bucket_method` | `fixed_start_key` | Recommended for IMDB (fast) |
| `--sampling_percentage` | `1.0` | 100% sampling rate |
| `--sampling_type` | `ss` | Stratified sampling |
